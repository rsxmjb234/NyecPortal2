# Per-QE data isolation and 5-view build pipeline for Marcus demo

This change rewrites the Marcus synthetic data bundle from a flat 5-source structure to a 15-source, per-QE-subfolder layout (5 QEs × 3 facilities), adds TRN discharge summaries as a third artifact type alongside CCDs and ORUs, and rebuilds the build pipeline to produce 5 independent QE portal views plus a landing page. Rochester RHIO is removed everywhere — SOURCES, volume reports, QE color maps, and the generated data files. The commit messages report successful builds: 45 files generated (15+15+15), 3 MRNs per view with no cross-QE leakage, and all 5 HTML outputs verified.

Watch for: the `importlib.reload()` pattern in build_home.py is correct but fragile if build_smart ever gains non-resettable module state (likely); EID prefixes are shared across HEALTHIX and HEALTHECONN QEs, which is semantically confusing though functionally harmless (confirmed, non-blocking).

**Verdict**: APPROVED

## High-level view

The data generator (`build_marcus_bundle.py`) now produces 15 CCDs, 15 ORUs, and 15 TRNs organized into `marcus_bundle/{qe_lower}/{ccda,oru-hl7,trn}/` subfolders. Each source gets a unique MRN and EID, uses a distinct base Synthea CCD within its QE, and generates varied lab values and encounter types.

The build orchestrator (`build_home.py`) uses env vars to point each renderer at the right QE subfolder. HIXNY gets a fresh `import build_smart`, HEALTHeLINK gets `import build_chart`, Bronx gets `import build_bronx`, and Healthix/HealtheConnections use `importlib.reload(build_smart)` to re-execute the module with updated env. The three per-QE renderers each gain a `CHART_TRN_DIR` env var and a TRN glob to ingest the new discharge summaries.

Rochester RHIO removal is thorough: gone from the SOURCES list, from Report 1 hardcoded data, from both QE_COLORS maps, from the QES card list in index.html, and filtered out of hosp_data.js and nonhosp_data.js via an `EXCLUDE_QES` set in build_reports.py. The deploy script adds the two new HTML files (`marcus_healthix.html`, `marcus_healtheconn.html`).

<summary>Issues (2)</summary>

1. **Reload fragility in build_home.py** — `importlib.reload(build_smart)` works today because all state comes from env vars at module scope, but any future addition of persistent module-level state (registries, caches, mutable defaults) would cause cross-QE data bleeding. A comment documenting this constraint would prevent regressions. (likely)
2. **Shared EID prefix across QEs** — HEALTHIX and HEALTHECONN both use `HE-EID-*` prefixes for their enterprise IDs. Values are unique so there's no functional collision, but the prefix implies same-QE origin, which could confuse anyone inspecting the synthetic data directly. (confirmed, non-blocking)

## Base CCD reuse across QEs

Within each QE's 3 sources, the base CCDs are always distinct, providing clinical variety in the portal. Across QEs, 5 of the 10 unique base CCDs are reused — HEALTHECONN and BRONX share bases with HEALTHIX and HEALTHELINK respectively. Two QE views may display similar conditions and labs for different source identities. Per-QE isolation (the actual requirement) is enforced by folder structure and env-var routing, not by clinical content uniqueness, so this doesn't break the demo — but it's worth knowing if anyone compares views side-by-side.

## Reload pattern and `n_people` after reloads

The risk with `importlib.reload(build_smart)`: if build_smart ever accumulates module-level state that survives reload (a class registry, a `_cache = {}` dict, a decorator-based collector), the Healthix or HealtheConnections views could silently inherit data from the previous build. Today the module is stateless between reloads. A short comment at the reload callsite documenting this invariant would be cheap insurance.

The `n_people = len(build_smart.patients)` line after all builds captures the patient count from the last reload (HEALTHECONN), not from HIXNY. Since all QEs happen to have exactly 3 patients, the value is correct. If QE sizes ever diverged, the index page would show the wrong count.
